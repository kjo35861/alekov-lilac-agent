## 2. 새 환경 재현 절차 — 학생이 실제로 수행 후 증거 기입

아래는 **Windows PowerShell**에서 실행하도록 제공된 절차이며 실행했다는 기록이 아니다. 원래 작업 폴더가 아닌 **새 빈 폴더**를 사용한다. 새 Git 작업 공간 예시 `$HOME\alekov-reproduction-22`는 절대경로 의존이 아닌 사용자 홈 아래 상대적 위치다. 이미 존재한다면 덮어쓰지 말고 다른 새 폴더명을 사용한다.

```powershell
# ① 기존 작업 보존: 기존 프로젝트 폴더에서 별도로 git status --short를 확인
# ② 새 폴더 만들기: 없는 경로만 사용
$work = Join-Path $HOME 'alekov-reproduction-22'
if (Test-Path $work) { throw '이미 존재하는 폴더입니다. 다른 빈 이름을 사용하세요.' }
New-Item -ItemType Directory -Path $work | Out-Null
Set-Location $work
git clone https://github.com/kjo35861/alekov-lilac-agent.git
Set-Location .\alekov-lilac-agent

# ③ 제출할 커밋을 아래 실제 SHA로 바꾸고 정확히 체크아웃
git checkout --detach <40자리-최종-커밋>
git rev-parse HEAD
git status --short
node --version
npm --version
npm run check

# ④ 새 PowerShell에서 아래 실행 명령으로 서버 시작
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1

# ⑤ 브라우저 http://127.0.0.1:5189/ 접속 후 제공 메뉴 확인
# ⑥ 실행 창에서 Ctrl+C로 서버 종료
# ⑦ ④와 같은 명령으로 재실행, 다시 브라우저 확인
```

**중요:** `<40자리-최종-커밋>`은 그대로 입력하는 문자가 아니다. 제출하기로 확정한 실제 해시로 교체한다. 이 문서 작성 시점에는 최종 문서 커밋 생성 전이므로 해시를 추측하지 않았다. `git checkout --detach`은 원래 폴더를 건드리지 않고 새 복제본만 해당 커밋으로 고정한다. 기존 폴더의 토큰·인증서·비밀 환경변수·개인 SDP 설정·로컬 데이터베이스를 복사하지 않는다.

정상 시작 문구는 `tools/start-alekov.ps1` 원문에 `케셰브가 켜졌습니다. 브라우저에서 http://127.0.0.1:5189/ 을 여세요.`와 `서버가 응답한 것만 확인했습니다. AI 연결 상태는 화면에서 따로 확인해 주세요.`로 정의되어 있다. 제공 앱 기본 명칭 '케셰브'와 학생 Agent명 '라일락'은 별개이다. 문구가 실제로 출력됐는지, HTTP 200이 나왔는지, 메뉴가 작동했는지는 **미확인**이다.

## 5. 이동 가능한 설정과 의존성 경계

- 필수 파일: 이 Git 저장소의 `package.json`, `src/`, `public/`, `student/`, `tools/`, `vendor/`, `docs/`, `.env.example` (제공 코드·학생 문서 보존).
- `package.json`에서 `npm start`는 `node src/server.mjs`, `npm run demo`는 `node src/server.mjs --demo`, `npm run check`는 `node --check student/extension.mjs`로 지정됨. 직접 npm 패키지 의존성이 선언되지 않음.
- 기본 포트는 `5189`; 다른 PC에서도 같은 로컬 호스트 주소를 쓰며 비공개 호스트 URL을 코드에 쓰지 않는다.
- `.env.example`은 비밀 없는 견본이며, 실제 개인 호스트 연결·신원 매핑·AI 앱 승인·보관함·패키지 허용 목록은 **담당 운영자 제공 시 별도로 설정**한다. 이전 PC의 비밀 설정을 새 폴더로 그대로 복사하지 않는다.
- 새 환경에서 기본 서비스가 응답하는 것과 원천 SDP/AI 게이트/집행기 연결은 다른 검증이다. 연결이 없으면 disconnected·미지원·권한 준비 중 상태를 숨기지 않는다.
- `package-lock.json`은 GitHub 원문 확인 당시 발견하지 못했다. 설치·OSV 대조에 사용됐다고 주장하지 않는다.
- 브라우저 앱 제목/제공 스크립트에는 제공 기본 명칭이 남아 있으며, Agent 이름 '라일락'으로 코드 이름을 임의 변경하지 않았다.

## 6. 학생 데이터 보존·백업·복원 계획과 한계

이 저장소에는 학생 **소스/문서 버전**을 Git 커밋으로 보존한다. 다음은 실제로 백업·복원을 완료했다는 진술이 아닌 **계획**이다.

1. **원본 보호:** 기존 프로젝트와 Git 히스토리는 그대로 보존하고, 재현은 독립 복제 폴더에서 수행한다. `git status --short`로 커밋되지 않은 변경을 먼저 식별하고 무단 초기화·강제 푸시를 하지 않는다.
2. **소스 백업:** 저장소의 특정 40자리 커밋을 원격 GitHub에 보존하고, 필요하면 `git clone` 후 해당 SHA를 체크아웃한다. Git에 없는 로컬 파일·개인 설정·동작 중 자료는 이 방식으로 복원되지 않는다.
3. **보안/사용자 자료:** 본인 계정·기기·세션·감사 로그·XDR 경보는 운영자 관리 원천 시스템에서 조회하는 자료다. 학생 앱에서 전체 원천 데이터를 임의로 백업·반출하지 않는다. 원천의 백업·복원 및 보존 기간은 **담당자 정책 확인 필요**이며 이 프로젝트만으로 보장하지 않는다.
4. **비밀 설정:** 인증서·키·토큰·비밀번호·개인 설정 파일은 Git/화면 캡처/릴리스 산출물에 넣지 않는다. 다른 환경에서 필요하면 운영자의 승인된 재발급·호스트 연결 절차를 따른다.
5. **복원 검증:** 독립 새 폴더에 동일 커밋을 복제하고 `npm run check`, 시작/종료/재시작을 재실행해 소스 수준 재현을 확인한다. 연결 데이터 복구, 실제 조치 효과의 복원·취소 기능으로 해석하지 않는다.

## 7. 남은 문제·지원 범위·판정 구분

- 기본 원천 보안 조치 집행 연결은 준비되지 않았고, 실제 학생 계정에서의 실행 및 관측 효과는 미완료다.
- 17~18단계 실제 앱 AI 권한·모델 설명 요청 결과는 별도 운영 권한과 호출 결과가 필요하며 원문 확인만으로 성공을 보장할 수 없다.
- OSV 조회는 승인된 공개 패키지 및 정확한 설치 메타데이터에 한정되고, 미조회나 조회된 취약점 0건은 안전의 증거가 아니다.
- 학생 재현 기록·예제 화면·AI 원문 판정·실제 운영 시스템 확인은 구분한다. **22단계 원문 검토 통과가 실제 운영 인증, 전체 시스템 집행 연결 또는 v1.0 자동 인증은 아니다.**
- 수정이 필요하면 새로운 커밋을 기록하고 **변경된 동일 최종 SHA로 모든 실행 증거를 다시 연결**한다. 서로 다른 SHA의 부분 검증을 합쳐 최신 버전의 전체 성공으로 표시하지 않는다.
- 21~22단계 포털 제출은 저장소 URL·실제 40자리 커밋 해시를 직접 사용한다. 비공개 저장소 원문 JSON은 과제 화면의 `student-source-cli.mjs` 안내에 따라 프로젝트 밖 도구·출력 폴더를 사용한다. 제출·실제 보안 조치는 이 문서 작성만으로 실행되지 않는다.
